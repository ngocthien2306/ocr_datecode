khi user load recipe bằng cách call api (FE call restfull BE) thì BE bắn tín hiệu socket 
sang AI service để bắt đầu logic trigger. Tôi có code mẫu để đọc chân DI (0, 1, 2, 3) tuỳ theo config của người dùng trên FE
có 3 cách trigger lấy frame khi giá trị từ 0->1, 1->0 hoặc cả hai. mỗi lần chỉ đọc N frame tuỳ theo config của người dùng, mỗi frame cách nhau N ms delay (trong recipe có field Delay Trigger (ms) *)
để inference (hiện tại có class SuperPointMatcherTRT để template matching suy luận ra các vùng bbox/polygon) tìm ra vùng bbox/polygon dựa vào ảnh template để truy vấn ảnh target
phần trigger này ta giả lập call 1 api -> api gửi socket để trigger chụp ảnh và inference

trong recipe có thể có nhiều hơn 1 camera, 1 camera có thể có nhiều hơn 1 template 
số lần chụp N ảnh ở trên phụ thuộc vào số lượng template của camera 

tiếp theo là solution design camera 

ta sẽ có class CameraManagement để quản lý tất cả camera, và class Camera

khi FE call api connect qua BE, BE gửi socket tới CameraManagement, để add Camera vào dựa vào key Serial Number, mỗi camera hoạt động riêng biệt 
khi FE call api disconnect qua BE thì BE gửi socket tới CameraManagement để delele camera này

Cách để BE lấy frame gửi cho FE khi FE request capture hay live camera, đầu tiên là khi camera đc khởi tạo sẽ tạo shared_memory để lưu frame vào đây, 
bên BE lấy frame dựa vào serial number để lấy và gửi lại FE
