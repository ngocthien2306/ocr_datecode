  3.2. Trigger Cameras Group (trigger_handler.py:347-444)

  Đây là mechanism chính xử lý multi-camera với delays khác nhau:

  def trigger_cameras_group(cameras):
      # Tạo group ID duy nhất
      group_id = self._timer_counter += 1

      # Tạo capture group để track progress
      self._capture_groups[group_id] = {
          'cameras': cameras,
          'results': {},
          'expected_count': len(cameras),
          'completed_count': 0,
          'created_at': time.time()
      }

      # Schedule timer cho TỪNG camera với delay riêng
      for camera in cameras:
          delay_sec = camera.delay_trigger / 1000.0

          timer = threading.Timer(
              interval=delay_sec,
              function=_capture_and_register,
              args=(camera, group_id)
          )
          timer.start()

      # Schedule timeout timer (max_delay + 10s buffer)
      timeout_timer = threading.Timer(
          interval=max_delay + 10.0,
          function=_group_timeout,
          args=(group_id,)
      )
      timeout_timer.start()

      # RETURN NGAY - Không block polling thread!

  Cơ chế hoạt động:
  1. Mỗi camera có Timer riêng với delay riêng (camera.delay_trigger)
  2. Timers chạy song song, không đợi nhau
  3. Polling thread return ngay lập tức, không bị block
  4. Khi timer của 1 camera fire → gọi _capture_and_register()

  3.3. Capture And Register (trigger_handler.py:446-548)

  Chạy trong Timer thread khi delay hết:

  def _capture_and_register(camera, group_id):
      logger.info(f"[Group #{group_id}] Camera {camera.serial_number} timer FIRED!")

      # Capture IMMEDIATELY (no delay inside!)
      result = camera.execute_software_trigger_immediate()

      # Register result vào group (thread-safe)
      with group['group_lock']:
          group['results'][camera.serial_number] = result
          group['completed_count'] += 1

          # Kiểm tra nếu TẤT CẢ cameras đã complete
          if group['completed_count'] >= group['expected_count']:
              # TRIGGER INFERENCE!
              logger.info(f"[Group #{group_id}] ✅ All cameras completed!")

              # Emit event để trigger inference
              camera_manager._emit_event("frames_captured", {
                  "group_id": group_id,
                  "cameras": group['cameras'],
                  "results": group['results']
              })

              # Cleanup group
              del self._capture_groups[group_id]

  Điểm quan trọng:
  - Chỉ camera CUỐI CÙNG hoàn thành mới trigger inference
  - Inference xử lý TẤT CẢ frames của tất cả cameras cùng lúc (batch processing)

  5. CÁC VẤN ĐỀ TIỀM ẨN

  ⚠️ VẤN ĐỀ 1: CAMERA BANDWIDTH OVERLOAD

  Mô tả: Nếu nhiều timers fire cùng lúc, nhiều cameras cùng gọi ExecuteSoftwareTrigger() đồng thời

  Trong ví dụ của bạn:
  - t=3.6s: Camera1, Camera2 (Group #1) + Camera3 (Group #2) = 3 cameras cùng lúc
  - t=3.7s: Camera1, Camera2 (Group #2) + Camera3 (Group #3) = 3 cameras cùng lúc
  - t=4.0s: Camera1, Camera2 (Group #4) + Camera3 (Group #5) = 3 cameras cùng lúc

  Hậu quả:
  - USB bandwidth có thể bị quá tải (Basler cameras thường dùng USB3 ~400MB/s)
  - Camera có thể drop frames hoặc timeout khi RetrieveResult()
  - Ảnh hưởng: capture thất bại → group timeout → mất dữ liệu

  Kiểm tra trong code: camera.py:486-489
  grab_result = self.camera.RetrieveResult(
      2000,  # 2s timeout
      pylon.TimeoutHandling_ThrowException
  )
  Nếu camera bận, có thể throw exception!

  ⚠️ VẤN ĐỀ 3: INFERENCE QUEUE BUILDUP

  Mô tả: 5 inferences chạy trong khoảng 0.6s (từ t=3.6s → t=4.1s)

  Kiểm tra: camera_management_service.py:98-105
  if event_type == "frames_captured":

  Vấn đề: Nếu 1 inference mất >0.1s, các inference sau sẽ bị queue lại!

  Ví dụ: Nếu inference mất 0.5s mỗi lần:
  - Inference #1 (t=3.6s) → hoàn thành t=4.1s
  - Inference #2 (t=3.7s) → chờ đến t=4.1s → hoàn thành t=4.6s
  - ... Delay tích lũy!

  ✅ NHỮNG ĐIỂM TỐT:

  1. Non-blocking design: Polling thread không bị block, có thể xử lý triggers liên tục
  2. Per-camera delays: Mỗi camera có delay riêng, linh hoạt
  3. Thread-safe: Sử dụng locks đúng cách cho shared data
  4. Timeout protection: Có cơ chế timeout để cleanup groups bị stuck
  5. Statistics tracking: Monitor được hiệu suất hệ thống
